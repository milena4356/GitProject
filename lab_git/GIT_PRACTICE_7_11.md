# Лабораторная Git — пункты 7–11 (по схемам)

Репозиторий: `milena4356/GitProject`; рабочая ветка: `milena`. Основная ветка GitHub называется `main`, хотя в задании она названа `master`. Не сливай изменения в `main` без необходимости; PR для проверки: https://github.com/milena4356/GitProject/pull/1.

## 7. Перенести изменения своей ветки на основную

```bash
git fetch origin
git switch milena
git pull --ff-only origin milena
git switch -c practice/task-7
git rebase origin/main
```

Если возникнет конфликт, исправь файл и выполни:

```bash
git add <файл>
git rebase --continue
```

Повторяй для остальных конфликтов. Для отмены: `git rebase --abort`. Поскольку это упражнение с переписыванием истории, делай его в отдельной ветке. Если преподаватель требует merge, вместо rebase используй `git merge origin/main` в учебной ветке.

## 8. Отправить итоговое состояние на сервер

```bash
git status
git log --oneline --graph --decorate --all
git push -u origin practice/task-7
```

Если работа должна остаться в `milena`, после проверки перенеси нужные коммиты туда и отправь именно эту ветку.

## 9. Исходный граф и два целевых варианта

Исходный граф из задания:
```text
C1 -- C2 -- C3       (master)
       \\
        C4 -- C5     (test)
```

### 9a. Объединить C3 и C5 в C35

На учебной копии, где `master` указывает на C3, а `test` на C5:

```bash
git switch test
git merge --no-ff master -m "C35: merge C3 and C5"
git log --oneline --graph --decorate --all
```

Результат — merge-коммит C35 с двумя родителями: C5 и C3. Указатели `master` и `test` можно передвинуть на C35, если это соответствует рисунку.

### 9b. Получить линейную цепочку C1 → C2 → C3 → C4' → C5'

На учебной копии:

```bash
git rebase master test
git log --oneline --graph --decorate --all
```

Это переиграет C4 и C5 поверх C3, создав новые коммиты C4' и C5'. Указатель `master` остаётся на C3, `test` переходит на C5'.

### Бонус: C3 и C5 конфликтуют / не конфликтуют

Проверь два случая на отдельных ветках:
- Без конфликта: изменения C3 и C5 касаются разных файлов или непересекающихся строк.
- С конфликтом: оба коммита меняют одну и ту же строку несовместимым образом.

При конфликте исправь содержимое файла, затем `git add <файл>` и `git rebase --continue` (если конфликт возник при rebase) либо `git commit` (если при merge).

## 10. Два изменения как один коммит

Внеси любые два изменения, но закоммить их одним коммитом:

```bash
# измени два файла или сделай два отдельных изменения
git add <файл-1> <файл-2>
git commit -m "combine two changes"
```

Если по требованию преподавателя сначала должны появиться два коммита, создай их и затем объедини в учебной ветке:

```bash
git rebase -i HEAD~2
```

Оставь первый коммит как `pick`, второй отметь `squash` или `fixup`. Убедись, что результат содержит один коммит с обоими изменениями.

## 11. Преобразовать граф с ветками master, client, server

Целевая линейная последовательность слева направо по рисунку (от старых к новым):
`C1 → C2 → C5 → C6 → C8' → C9' → C3' → C4' → C10'`.

В целевом графе `master` и `client` указывают на C9', `server` — на C10'. Штрих означает новый SHA после переигрывания коммита. Исходные C8/C9 и C3/C4/C10 должны быть перенесены в указанном порядке на целевую линию; точные команды зависят от исходных SHA в локальном учебном репозитории.

Сначала посмотри реальные SHA и структуру:

```bash
git log --oneline --graph --decorate --all
git branch -avv
```

Используй `git rebase --onto <новая-база> <старая-база> <ветка>` или `git cherry-pick <SHA>` в отдельной учебной ветке, чтобы получить последовательность выше. Затем передвинь учебные указатели веток на нужные коммиты и проверь:

```bash
git log --oneline --graph --decorate --all
```

Не выполняй пункт 11 на `main` или рабочей ветке `milena`: он специально переписывает историю. Фото с GitKraken показывает аналогичный граф в другом репозитории, но не содержит SHA, поэтому по нему нельзя безопасно переписать историю этого проекта автоматически.
