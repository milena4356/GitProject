## Проверка программы

```bash
python lab_git/main.py
```

Введи два целых числа. Программа выводит их сумму. При вводе нецелого значения сообщает об ошибке.

## Просмотр истории и diff
```bash
git fetch origin
git log --oneline --graph --decorate --all
git log --oneline -- lab_git/main.py
git diff <SHA-раннего-коммита> <SHA-коммита-с-операцией> -- lab_git/main.py
git status
```

Подставь реальные SHA из `git log`; не используй условные обозначения `<...>` как буквальные значения.

## Синхронизация локальной ветки
```bash
git switch milena
git pull --ff-only origin milena
```

## Перенос на основную ветку
В задании сказано перенести изменения своей ветви на `master`. В этом репозитории основная ветка называется `main`. Перед переносом нужно получить актуальное состояние и проверить различия:

```bash
git fetch origin
git log --oneline origin/main..milena
git diff origin/main...milena
```

Не выполняй слияние в `main`, если преподаватель требует только показать перенос или если в основной ветке есть чужие изменения. Сначала согласуй способ сдачи.

## Упражнения по истории изменений (пункты 9–11)
В документе методички схемы для пунктов 9 и 11 не извлеклись в текстовом виде, поэтому точную требуемую топологию коммитов по нему восстановить нельзя. Для демонстрации операций используй отдельные временные ветки, не изменяя `main`:

```bash
git switch milena
git switch -c practice/history
```

Сделай несколько независимых коммитов и изучи граф:

```bash
git log --oneline --graph --decorate --all
```

Объединение последних трёх коммитов в один в учебной ветке:

```bash
git rebase -i HEAD~3
```

В редакторе оставь первый коммит как `pick`, а следующие пометь `squash` или `fixup`. Это переписывает историю текущей ветки, поэтому выполняй только на учебной ветке.

Чтобы рассмотреть конфликты, создай две временные ветки от одного состояния и измени одну и ту же строку по-разному. При слиянии разреши конфликт вручную, затем выполни `git add <файл>` и `git commit`. Для отмены незавершённого слияния используй `git merge --abort`.

## Ограничения
GitHub API позволяет записывать файлы и создавать коммиты в удалённой ветке, но не выполняет команды Git в локальном клоне пользователя. Поэтому локальный `git pull`, фактическое разрешение конфликтов, интерактивный `rebase` и проверка программы в локальной среде должны быть выполнены в терминале. Схемы пунктов 9 и 11 следует сверить с изображениями в исходной методичке перед точным воспроизведением.
